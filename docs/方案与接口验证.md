# 知乎Lite · 方案与接口验证

2026-10-06。工作目录由用户指定为 Documents/ChatGPT/ZhihuLite；名称和图标由用户最终指定。

## 调研

只研究接口与交互，客户端独立实现，未复制参考项目实现。

- [Zhihu++](https://github.com/zly2006/zhihu-plus-plus)：HotListViewModel 使用 Web v3 热榜；QuestionFeedViewModel/AnswerNavigator 封装问题分页；IdentityProtocol 区分 App 版本与账户令牌；回答内容独立缓存。具有本地推荐和多种数据源，不应假设网页游客链路一直有效。
- [Hydrogen](https://github.com/zhihulite/Hydrogen)：hot_model 使用 v3 热榜；question_model 使用 v4 questions/{id}/feeds，回答 model 使用 v4 answers，作者和正文分离。登录变化后更新 Cookie/Bearer，非必要能力延迟登录。
- [知乎--](https://github.com/huamurui/zhihu-minus-minus)：appApi 对 questions/feeds 使用 3.0.89、x-page-id 172；游客推荐可回退 explore/guest/feeds；问题详情区分登录的 Web API 和游客 App API。页面不能把一种失败误判成全部接口失败。
- [Telegram Android](https://github.com/DrKLO/Telegram)：阅读 Theme.java 的独立背景/细分隔线/ActionBar/文字颜色 token；采用紧凑顶栏和列表，不使用品牌资产。无需引入 Telegram 工程。

## 实测（电脑与 ADB 设备）

- GET api.zhihu.com/topstory/hot-lists/total?limit=50，App UA + x-api-version 3.0.93：电脑 HTTP 200，含 title_area/excerpt_area/metrics_area/link。热榜必须兼容这种结构和 Web target question 结构。
- GET www.zhihu.com/api/v3/explore/guest/feeds?limit=15&ws_qiangzhisafe=0：电脑 HTTP 200，真实 answer target，正文可能截断，必须检查 content_need_truncated/force_login_when_click_read_more。
- Web v3 热榜：401/403；不以假数据替代。
- Web v4 问题、问题回答/feeds、单条回答：403。
- App questions、questions/feeds：403 10003 请求参数异常；App answers：403 验证要求。试过参考项目的 endpoint 版本/include/header，仍受限。
- PKX110 设备 curl 对 Web 热榜 401，App question answers 403。通过 App 自身网络再验证。

进一步调查找到当前有效的游客结构化阅读链路：

- `GET api.zhihu.com/next-render`，`scenes=question_feed` + `collection_id` + `collection_type=question` + 服务端上下文，HTTP 200；返回真实回答列表与 `paging.next`。首个请求的上下文回答 ID 取自实时游客推荐，不硬编码内容 ID，响应严格按所属问题过滤。
- `GET api.zhihu.com/next-content-render?offset=0&url_token={answerId}&content_type=answer`，HTTP 200；返回段落、图片、引用、表格、列表等结构化正文。分页对象可能是 JSON 字符串，URL 中可能出现字面量 `\u0026`，需解析后保留服务端 continuation。
- 验证热门问题回答分页：第一页 5 条、第二页 5 条，所有条目的 question.id 与请求一致。
- 验证两个真实回答：一个 14 段、4 张图片；另一个 25 段、分 2 页，到 `is_end=true`。图片 CDN HTTP 200。报告在 `api-verification.json`，脚本为 `scripts/verify_public_chain.py`。
- PKX110 上 `next-content-render` 返回 14 段真实正文。设备原生界面已通过“热榜 → 问题 → 回答”的导航，记录在 `device/navigation-result.json`。

旧接口失败不会伪造结果；新游客链路已打通。最新排序、搜索、评论、作者完整主页、关注与知乎账户收藏仍不应宣称全部验收：未登录访问目前 403；这些页面提供真实错误及官方网页入口。知乎账户收藏尚未实现。本地收藏完全独立于此限制。首页游客推荐的当前响应无 paging；没有伪造 next URL 或假分页，标准分页能力需继续验证 App 推荐接口。

回答分段懒加载，完整性以服务端结束标记判断；错误和登录提示明确显示。认证页面由用户操作，不处理用户账号密码，不规避验证码。Cookie 的持久化副本使用 Keystore AES-GCM；退出验证页清理 WebView Cookie，系统备份与设备迁移全部排除。

## 架构与文件

Kotlin + Compose → ReaderViewModel → ZhihuRepository → ZhihuApi / Room。独立 SessionStore 使用 Android Keystore AES-GCM；Cookie 不写日志，仅允许知乎域 API 读取。无后台服务、广告、分析、推送 SDK。

MainActivity.kt：主题、路由、四个主 Tab、搜索、问题、回答、评论、作者、本地记录、设置、受控验证 WebView。
Data.kt：Model、状态、集中网络封装、缓存、Repository、ViewModel。
SessionStore.kt：加密 Cookie 与清理。
SavedContent.java / SavedDao.java / LiteDatabase.java：Room 收藏/历史/稍后阅读。
StructuredContent.kt：服务端结构化段落和分页转换，保留链接与文本格式。
RichBody.kt：HTML 转原生段落、标题、引用、粗斜体、链接、列表、代码块、图片。
AndroidManifest.xml：只有 INTERNET 权限；禁止明文请求及系统备份。

## Design system

- 蓝 #0084FF；主色只用于动作/链接/选中。
- 背景白/深色，主文字 #202124，副文字 #737B86，分隔线低对比 0.5dp。
- 顶栏 56dp，底栏 56dp；列表 16dp 内边距，无大圆角卡片。
- 问题标题 18sp，摘要 14sp 22sp 行高；阅读标题 23sp，正文 17sp / 28sp；边距 18dp。
- 日间/夜间/跟随系统；阅读字号 15/17/19/21，设置保存在本机。
- 回退保留页面对象与列表滚动状态；加载/空/错误均有明确文字和重试。热榜 5 分钟缓存，缓存先显示、后台刷新，分页依赖服务端 paging.next。
